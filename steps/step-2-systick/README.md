# step-2-systick：用系统计数器做精确节拍

> 状态：✅ 双轨均已上板（1ms 节拍、LED 每秒交替，用户目视确认；秒表精算待补）
>
> 对应教程章节：第 04 章（写作中）

## 目标

把第 03 章"数圈儿"的忙等延时换成硬件计数：用 QingKe V5 的系统计数器（SysTick）产生
**精确 1ms 节拍**，软件累计 1000 拍翻转一次 LED，得到 1Hz 交替。

## SysTick 布局（考据 + 本机实测）

H417 有**两路全局系统计数器，每核一路**（来源：ch32-rs `svd/fixed/ch32h417.svd` +
Zephyr `dts/riscv/wch/qingke-v5f.dtsi`，本机实测确认）：

| 实例 | 寄存器 | 归属 | 中断号 |
|------|--------|------|--------|
| STK0 | CTLR `0xE000F000`、ISR `0xE000F004`、CNT `0xE000F008`、CMP `0xE000F010` | V3F | IRQ 12 |
| STK1 | CTLR `0xE000F080`、CNT `0xE000F088`、CMP `0xE000F090`（标志仍在 `0xE000F004` bit1，`0xE000F084` 为同位镜像） | **V5F** | IRQ 13 |

> ⚠️ **V5F 镜像必须用 STK1**。用 STK0 的话节拍中断发给正在 `wfi` 睡觉的 V3F，本核永远等不到节拍。

`CTLR` 位段（SVD 标注均为 read-write）：

| bit | 名称 | 含义（本机实测） |
|-----|------|------------------|
| 0 | EN | 计数器使能 |
| 1 | IE | 计数中断使能（本章用轮询，中断留第 06 章） |
| 2 | NO_RTC | 计数时钟源选择：0 → 慢档，1 → 快档 |
| 3 | AUTO_RELOAD | 匹配后自动重装 CNT |
| 4 | DOWN_MODE | 倒计数 |
| 6 | CID | 内核寄存器分配标志：**软件不写、硬件自置**（写 `0x0D` 读回 `0x4D`） |

## 测频实录：计数源到底多快

用测频固件（`make measure.bin`：计数器自由跑 + CPU 空转），调试器隔固定时间读 `STK1_CNT`，
两点差分求速率：

```
NO_RTC=1（写后读回 CTLR=0x45）
  103,804,115 → 852,044,549 → 1,602,376,703 → 2,348,551,675 → 3,092,953,326 → 3,841,408,196
  逐段：100.2 / 100.8 / 100.7 / 100.8 / 101.0 MHz        均值 ≈ 100.72 MHz
NO_RTC=0（写后读回 CTLR=0x41）
  333,673,225 → 414,179,847 → 494,452,988                ≈ 12.6 MHz（正好是快档的 1/8）
```

于是 1ms = `100,720,000 / 1000 = 100,720` 个计数，`CMP = 100719`（`0x1896F`）。

> 计数源与内核主频的分频关系（是 HCLK 还是 HCLK/8？）留第 07 章时钟树实测确认；
> 本章只依赖"数出来的速率"——这正是没有资料时的正确姿势。

## 两个必须实测的语义坑

- **清标志是写 0，不是写 1**：F1 惯性写法 `ISR = flag`（写 1 清除）在 H417 上毫无作用——
  实测关掉计数器后写 `0xE000F004 = 2`，标志仍是 `0x2`；写 `0` 才清零（`0xE000F084` 同步归零，确认是同位镜像）。
  写错的后果很隐蔽：轮询每次都"立刻成功"，`ms` 以 MHz 级狂增，LED 交替快到肉眼看起来**两颗常亮**。
- **使能后几乎立刻就能读到标志置起**：所以清标志要放在写 `CTLR` 使能**之后**，否则第一拍提前触发。

## 构建与烧录

```bash
# C：waker.bin + step2.bin（TICK_HZ 默认取实测均值）
make -C steps/step-2-systick/c

# 测频固件（先测频再出节拍固件时用）
make -C steps/step-2-systick/c measure.bin STK_NO_RTC_SEL=1

# Rust 轨（零第三方依赖，产物用 objcopy 提取）
cd steps/step-2-systick/rust && cargo build --release

wlink flash -e -a 0x08000000 c/waker.bin     # 唤醒器，带整片擦除
wlink flash    -a 0x08010000 c/step2.bin     # V5F 应用
```

> 改 `TICK_HZ` / `STK_NO_RTC_SEL` 这类命令行宏不会改动文件时间戳，默认不会触发重编——
> 本 Makefile 用 `FORCE` 依赖保证应用始终重编，否则会烧到旧镜像（踩过，代价是白测一轮）。

## 验证

1. **目视**：两颗蓝灯以约 1 秒一次的节奏交替（不再是"两颗常亮"）——已确认。
2. **秒表**：数 10 次交替应 ≈ 10 s（节拍精度受速率测量误差限制，约 ±1%）。
3. **调试器**（沿用 step-0 的采样法）：halt 后应读到
   `STK1_CTLR=0x4D`、`STK1_CMP=0x1896F`、`STK1_CNT < CMP`（证明自动重装在工作）、
   `GPIOE_CFGLR=0x00003300`（PE2/PE3 推挽输出）、`OUTDR` 在 `0x04`/`0x08` 之间切换。

   注意一个观测副作用：**halt 期间上千个节拍会塌缩成一拍**（计数器全局继续走，但软件被冻住），
   所以挂着调试器采样时 LED 看起来比 1Hz 更慢——这是手段的失真，不是固件的 bug。
