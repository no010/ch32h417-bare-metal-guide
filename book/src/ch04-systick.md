# 04 SysTick 与精确延时

第 02、03 章的延时都是"数圈儿"：

```c
for (;;) { GPIOE_BSHR = ...; delay(500000); }   /* 多久？取决于主频和取指等待 */
```

它有三个毛病：**时长跟主频绑定**（第 07 章一改时钟就全飘）、**占着 CPU 空转**、**谈不上精确**。
本章把时间交给硬件：QingKe V5 的系统计数器（教程里沿用大家熟悉的叫法——SysTick），
做出真正的时间基准。代码在 [`steps/step-2-systick`](../../steps/step-2-systick)。

## H417 的 SysTick 长什么样

先给结论（考据 + 本机实测）：**H417 有两路全局系统计数器，每核一路**。

| 实例 | 寄存器 | 归属 | 中断号 |
|------|--------|------|--------|
| STK0 | CTLR `0xE000F000`、ISR `0xE000F004`、CNT `0xE000F008`、CMP `0xE000F010` | V3F | IRQ 12 |
| STK1 | CTLR `0xE000F080`、CNT `0xE000F088`、CMP `0xE000F090` | **V5F** | IRQ 13 |

标志位共用一个寄存器：`0xE000F004` 的 bit0 = STK0、bit1 = STK1（`0xE000F084` 是同位镜像，实测同步变化）。

`CTLR` 位段（SVD 标注均为 read-write）：

| bit | 名称 | 含义（本机实测） |
|-----|------|------------------|
| 0 | EN | 计数器使能 |
| 1 | IE | 计数中断使能（本章用轮询，第 06 章再接中断） |
| 2 | NO_RTC | 计数时钟源选择：0 → 慢档，1 → 快档 |
| 3 | AUTO_RELOAD | 计数值与 CMP 匹配后自动重装 |
| 4 | DOWN_MODE | 倒计数 |
| 6 | CID | 内核寄存器分配标志：**软件不写、硬件自置** |

> ⚠️ **V5F 的镜像必须用 STK1。** 用 STK0 也能计数，但节拍中断是发给正睡在 `wfi` 里的 V3F 的——
> 本核永远等不到。Zephyr 的设备树注释把这条写得很直白，我们也实测确认。

和 Cortex-M 的 SysTick 对照着看，差异很有意思：

| | Cortex-M SysTick | QingKe V5 系统计数器 |
|---|---|---|
| 位置 | 系统区寄存器 | 内存映射外设（`0xE000F000` 区） |
| 归属 | 每核一个 | 每核一路、但地址是全局的（两路并排摆着） |
| 计数位宽 | 24 位 | 32 位 |
| 重装 | LOAD 寄存器 | CMP 匹配 + AUTO_RELOAD |
| 计数源 | SYSTEM 或 EXT | `NO_RTC` 两档选择 |

`CID`（bit6）是个好教材：我们写进 `CTLR` 的是 `0x0D`，**读回来是 `0x4D`**。
硬件替这一路分配了一个内核寄存器。这也是"裸机读回值不等于写入值"的第一次现场演示。

## 没有手册，怎么知道它多快：测频实录

位段名字会骗人，跑出来的数字不会。所以我们先烧一版**测频固件**：`CMP = 0xFFFFFFFF`、
关自动重装、让计数器自由跑、CPU 空转，然后用调试器隔固定时间读两次 `CNT` 做差分。

```
NO_RTC=1（写后读回 CTLR=0x45）
  103,804,115 → 852,044,549 → 1,602,376,703 → 2,348,551,675 → 3,092,953,326 → 3,841,408,196
  逐段速率：100.2 / 100.8 / 100.7 / 100.8 / 101.0 MHz      均值 ≈ 100.72 MHz

NO_RTC=0（写后读回 CTLR=0x41）
  333,673,225 → 414,179,847 → 494,452,988                 ≈ 12.6 MHz（正好是快档的 1/8）
```

两档差 8 倍，说明 `NO_RTC` 选的是同一个时钟的两个分频。于是：

```
1 ms 的计数值 = 100_720_000 / 1000 = 100_720      →  CMP = 100_719 (0x1896F)
```

这一节的方法论比数字更重要：**资料缺失时，先量再用**。至于这一档计数到底是 HCLK 还是 HCLK/8，
等第 07 章把时钟树配起来再交叉验证——本章只依赖"数出来的速率"。

## 语义坑：清标志要写 0（H417 不是 F1）

第一版固件我们照搬 F1 的习惯写"写 1 清除"：

```c
STK_ISR = STK1_FLAG;      /* ← 在 STM32 F1 上这是标准动作，在 H417 上完全无效 */
```

现象非常诡异：**两颗蓝灯看起来都常亮**。逻辑链是这样的——标志清不掉 → 轮询
`while ((STK_ISR & flag) == 0)` 每次都"立刻成功" → `ms` 以 MHz 的速度往上加 →
每 1000 次循环翻转一次 LED → 交替频率上万赫兹 → 人眼只看得到"两颗都亮着"。

定位手段还是那一套：halt 读寄存器。我们看到 `CNT` 确实在自动重装区间里循环
（`CNT < CMP` 恒成立），说明节拍硬件是好的，问题在软件对标志寄存器的理解。
于是做一次干净的清除语义实验——**先把计数器关掉**（`CTLR=0`，免得下一拍又来置位），
然后分别尝试两种写法：

```
关计数后 ISR = 0x2
写 0xE000F004 = 2  →  仍读回 0x2    ✗ 写 1 不清
写 0xE000F004 = 0  →  读回 0x0      ✓ 写 0 才清零
                       （0xE000F084 同步归零，确认两处是同一标志的镜像）
```

结论：**SVD 标它 read-write 是真话——这就是一个普通可写的标志寄存器，清标志写 0。**

顺带还踩到第二个细节：**使能的瞬间标志几乎立刻就置起了**，所以清标志必须放在写完 `CTLR`
之后，而不是之前。初始化顺序因此是：

```c
STK1_CMP  = TICK_HZ / 1000UL - 1UL;
STK1_CNT  = 0;
STK1_CTLR = STK_EN | STK_NO_RTC | STK_AUTO_RLD;
STK_ISR   = 0U;                       /* 使能之后再清 */
```

Rust 轨是同一段逻辑（`steps/step-2-systick/rust/src/main.rs`）：

```rust
write_volatile(STK1_CMP, TICKS_PER_MS - 1);
write_volatile(STK1_CNT, 0);
write_volatile(STK1_CTLR, STK_EN | STK_NO_RTC | STK_AUTO_RLD);
write_volatile(STK_ISR, 0);
```

主循环就是"等一拍、清一拍、数到 1000 就翻转 LED"：

```c
while ((STK_ISR & STK1_FLAG) == 0U) { /* 等一个 1ms 节拍 */ }
STK_ISR = 0U;                          /* 写 0 清除 */
if (++ms >= 1000UL) { ms = 0; GPIOE_BSHR = ...; }
```

本章刻意**不打开 `IE`**：先用轮询把时间基准建立起来，中断交给第 06 章（那时正好用这一路
计数器演示节拍中断）。

## 一个观测副作用：halt 会让软件漏拍

挂着调试器采样时，你会发现 LED 比 1Hz 慢得多。原因不是 bug：计数器是**全局**的，
内核被 halt 住它照常走，但软件冻在原地；等 resume 之后，标志早已置起，
上千个节拍塌缩成一拍。所以"调试器视角的时间"是被观测手段压缩过的——
这也顺手证明了这一路计数器不依附于内核运行。

## 精度与改进

现在的时间基准精度受限于速率测量本身（采样窗口 ±1% 量级），实测表现是"每秒一次交替，
10 次约 10 秒"。想再往上提，有三条路，都会在后续章节兑现：

1. **第 07 章**把时钟树配好后，主频已知 → `TICK_HZ` 可以直接算出来，不再靠量。
2. **第 05 章**接上 UART，让固件自己打时间戳，用主机侧时间轴对齐校准。
3. 长期精度（晶振温漂、RTC 域）属于第 07/08 章的话题，本教程不追求石英级计时。

## 上板验证

- 现象：两颗蓝灯以约 1 秒一次的节奏交替（**不再是"两颗常亮"**）；C 轨与 Rust 轨均已烧录复核。
- 调试器读数：`STK1_CTLR = 0x4D`、`STK1_CMP = 0x1896F`、多次采样 `STK1_CNT` 恒小于 CMP
  （自动重装在工作）、`GPIOE_CFGLR = 0x00003300`、`OUTDR` 在 `0x04` ↔ `0x08` 之间切换。
- 完整命令与原始读数留在 [`step-2-systick/README.md`](../../steps/step-2-systick/README.md)。

## 小结

- H417 有两路全局系统计数器，**V5F 用 STK1 @`0xE000F080`**（IRQ 13）；STK0 归 V3F。
- 计数速率不靠猜：测频固件 + 调试器差分 → `NO_RTC=1` ≈ 100.72 MHz，`=0` ≈ 12.6 MHz（1/8）。
- 清标志**写 0**（不是 F1 的写 1）；清标志要放在使能之后。
- 有了可靠的时间基准，下一章就可以让芯片"说话"——UART 与 `printf`。
