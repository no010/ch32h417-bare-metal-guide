# 00 写在前面：方法论与定位

## 这不是翻译

[cpq 的《Bare Metal Programming Guide》](https://github.com/cpq/bare-metal-programming-guide)教会了很多人一件事：**MCU 编程没有魔法**。没有 HAL 的时候你并没有失去什么——你失去的只是别人替你做的决定。

本教程采用同样的方法论，但选择了完全不同的战场：**WCH CH32H417**，一颗 2026 年初发布的双核 RISC-V MCU。区别在于：

1. cpq 教 STM32 时，全世界已经替你踩过二十年的坑；而我们面对的这颗芯片，**坑还没人踩**。你将看到寄存器是怎么从参考手册的表格里被逐位确认、从示波器上被证实的——这个过程本身就是教程的一部分。
2. cpq 只有 C；我们**每章提供 C 与 Rust 两套实现**。同一段裸机逻辑，C 写出来是什么样、Rust 写出来是什么样、Rust 的类型系统能在编译期拦住哪些 C 的事故——对照着看，两边都会更懂。

## 为什么是 CH32H417

- **双核**：QingKe V5F（RV32IMABCF，最高 400MHz）+ V3F（RV32IMAFCB，最高 160MHz）。单核教程遍地都是，双核 bring-up 的中文原创教程几乎空白。
- **外设豪华**：USB 3.2 Gen1（自带 PHY）、10/100M 以太网（MAC+PHY）、500MB/s UHSIF、SerDes、Type-C/PD、3×CAN、LTDC、双 5Msps ADC + 20Msps HSADC。
- **生态正好在临界点**：官方 [openwch/ch32h417](https://github.com/openwch/ch32h417) 提供 EVT 例程；Rust 社区 [ch32-rs](https://github.com/ch32-rs) 的 PAC 支持刚合入、HAL 正在 bring-up。跟着本教程走完，你会同时理解芯片和生态两件事。

## 四条原则

1. **每一步可跑**。每章的 `steps/step-N-*` 都是完整工程，`make` 或 `cargo build` 就能出固件，烧进去就能看到现象。
2. **无黑盒**。不使用官方外设库，启动代码、链接脚本、寄存器访问全部手写并解释为什么。
3. **真机验证**。每个示例标注验证状态：✅ 已上板 / 🧪 可编译待上板 / ⏳ 计划中。我们不做没跑过的"教程式伪代码"。
4. **考据寄存器**。所有地址与位段注明出处（参考手册章节 / 官方例程 / 社区考据数据），推测与证实分开标注。

## 你需要的前置知识

- 会用 C 或 Rust 写最基本的程序（另一门语言可以边学边对照）
- 知道什么是编译、链接；不要求读过链接脚本
- 不需要 ARM/RISC-V 汇编基础——用到哪条讲哪条
